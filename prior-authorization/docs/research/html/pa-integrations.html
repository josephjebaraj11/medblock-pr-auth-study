1. Swimlane: a PA request across EHR, clearinghouse, and payer

This is the modern, FHIR-based path a PA request takes today — one lane per organization.

sequenceDiagram participant Clinician participant EHR participant CH as Clearinghouse participant Payer Clinician->>EHR: Places order EHR->>Payer: CRD: needs PA? Note: the clearinghouse rarely disappears — most traffic still passes through an intermediary rather than a direct EHR↔payer connection.

These are two separate pipelines, not one. Pharmacy PA runs on NCPDP standards through PBMs and already has high adoption; medical PA is the one CMS-0057-F targets with FHIR. A drug request and a procedure request never meet in the same system.
CMS grants enforcement discretion: a payer can run fully FHIR-based without filing a separate X12 278 — but most still translate internally to older adjudication engines.
